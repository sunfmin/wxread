wxread contact: one contact of the account, in full, by its id.

WHEN TO RUN IT
  To see who one contact is: a person, a group or an official account.
  Run by you or an agent, once the keys are supplied; it changes nothing.

WHAT IT READS
  The account's contact/contact.db and head_image/head_image.db under its
  db_storage, each with the WAL beside it (what WeChat wrote last), with
  their keys: the file --keys names, else the contents of WXREAD_KEYS.
  Each is decrypted into memory and read there. It writes nothing,
  anywhere: no decrypted byte reaches the disk.

USAGE
  wxread contact <id> [--account <id>]

  <id>              the contact's id, as `wxread contacts` answers it: a
                    wxid, a group's <n>@chatroom, an official account's gh_...
  --account <id>    the account to read, as `wxread doctor` names it;
                    with only one logged in, that one

WHAT IT ANSWERS
    account   the account read: its directory's name, as doctor's id
    contact   {id, display_name, name, remark, alias, signature, kind,
              has_avatar}:
              id            the id asked for
              display_name  as WeChat shows it: the account's remark,
                            else its name; "" for neither
              name          what it calls itself; "" for none
              remark        what the account calls it; null for none
              alias         the WeChat ID it chose (微信号); null for none
              signature     its signature; null for none
              kind          "person", "group" or "official_account"
              has_avatar    whether WeChat holds its avatar

TRIPS YOU UP
  - An id is matched exactly: a name, a remark or a WeChat ID is not one.
    An unknown id is an error whose fix is `wxread contacts --query`,
    which finds it by any of them.
  - A group's members and notice are `wxread group <id>`'s.
  - The keys must open both databases: one missing is an error naming it,
    whose fix is `sudo wxread keys`, then supplying the keys again.
