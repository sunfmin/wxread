wxread search: the messages of every chat that hold a text, newest
first, a page at a time.

WHEN TO RUN IT
  To find what was said without knowing the chat: a word, a link's
  title, a file's name. Run by you or an agent, once the keys are
  supplied; it changes nothing. `wxread messages --chat <id>` then reads
  the conversation around what it found.

WHAT IT READS
  WeChat's own full-text index of the chats (message/message_fts.db under
  the account's db_storage) when the account has one, the message
  databases (message/message_<n>.db, and message/biz_message_<n>.db for
  official accounts) and contact/contact.db, each with the WAL beside it
  (what WeChat wrote last), with their keys: the file --keys names, else
  the contents of WXREAD_KEYS. Each is decrypted into memory and read
  there, after its key is checked against its first page. It writes
  nothing, anywhere: no decrypted byte reaches the disk.

  What WeChat has indexed is searched in its index, by the text WeChat
  indexed of each message; what it has not indexed yet (the newest
  messages, a database it has no range of) is read message by message
  and searched by the same text, taken from its kind. Without an index,
  every message is read.

OPTIONS
  <text>            what to find, in any case and with or without spaces
                    between its words: a message is found when the text it
                    is searched by holds it; quote it when it holds a space
  --chat <id>       only this chat's messages, its id as `wxread chats`
                    lists it (a wxid, or a group's <n>@chatroom)
  --from <time>     the first time read, itself included
  --to <time>       the time reading stops before, itself left out
                    A time is RFC 3339 with its offset
                    (2026-10-20T09:30:00+08:00, 2026-10-20T01:30:00Z), or a
                    date (2026-10-20), its midnight in UTC.
  --account <id>    the account to read, as `wxread doctor` names it;
                    with only one logged in, that one
  --limit <n>       how many messages a page holds, 1 to 1000; 100 unless
                    given
  --cursor <next>   start after the page that answered this `next`, with
                    the same <text>, --chat, --from and --to

WHAT IT ANSWERS
    account   the account read: its directory's name, as doctor's id
    query     the text searched for, as given
    searched  how: "wechat_index" when WeChat's index was searched and what
              it has not indexed yet was read message by message;
              "messages" when the account has no index and every message
              was read
    messages  [{chat, matched, id, at, sender, kind, <kind>, type,
              subtype, content}], newest first across every chat:
              chat         the chat it was said in: {id, display_name},
                           as `wxread chats` names it
              matched      the text it was found in: what WeChat's index
                           holds of it, or the same text taken from its
                           kind
              id, at, sender, kind, <kind>, type, subtype,
              content      as `wxread messages --help` says
    next      pass it as --cursor for the next page; null on the last one

WHAT A MESSAGE IS SEARCHED BY
  The text WeChat indexes of it, by its kind:
  text, quote    its words (a quote's reply, not what it quotes)
  link           its title and summary
  file           its name
  location       its name and address
  card           the name the card gives the contact it shares
  forward        its title and what each message in it says
  note           the words of its paragraphs, and its places' names and
                 addresses and its files' names
  solitaire      all a 接龙 shows: its title and each entry, numbered
  transfer, red_packet
                 its memo
  group_notice   its text: a group's notice posted into its chat
  The rest are not searched: find them with `wxread messages`:
  image, video, voice, sticker
                 media, whose words WeChat does not index
  call           a voice or video call, {medium, state, seconds, text}:
                 voice or video, connected, cancelled, declined or
                 missed, and how many seconds a connected one lasted
  recall, nudge, join, leave, renamed, system
                 WeChat's notices

TRIPS YOU UP
  - The text is found inside words, ignoring case: "crag" finds "Crags"
    and "CRAG". It is one text, not words to find apart.
  - Whitespace does not decide a match, in the text or in the message:
    "15万行" and "15 万行" both find "写了 15 万行" and "写了15万行".
    Spaces between Chinese and Latin text or digits are put in
    inconsistently, so none is needed and none is in the way.
  - A query that finds nothing is an empty list, exit 0, not an error.
  - The chat id is exact: a group's ends in @chatroom. A chat none of the
    account's message databases holds is an error pointing at
    `wxread chats`.
  - Paging is by where each message was when the page was read: one sent
    since is not on a later page, and a fresh run from the newest shows
    it.
  - The keys must open contact/contact.db, every message database and,
    when the account has one, message/message_fts.db. One missing, or one
    that no longer opens its database (WeChat created its databases again:
    logging out and in, some updates), is an error naming the database;
    its fix is `sudo wxread keys`, then supplying the keys again.
  - Several accounts logged in is an error naming them: pass --account.
