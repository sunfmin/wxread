wxread voice: one voice message written as a file that plays, and what
WeChat heard in it.

  wxread voice <id> --chat <chat> --out <path>

WHEN TO RUN IT
  To listen to a voice message, or to read what it says, once `wxread
  messages` has answered it as "kind": "voice" with its id. Run by you or
  an agent, once the keys are supplied; it changes nothing of WeChat's.

WHAT IT READS
  The chat's message databases (message/message_<n>.db, and message/
  biz_message_<n>.db for official accounts), for the message itself, and
  the account's media databases (message/media_<n>.db), where WeChat keeps
  each voice message's sound by its chat and its id; each with the WAL
  beside it, with their keys: the file --keys names, else the contents of
  WXREAD_KEYS. Each is decrypted into memory and read there.

WHAT IT WRITES
  The one file --out names, and nothing else: the sound decoded from
  WeChat's SILK inside wxread, with no other tool, as a WAV (16-bit mono
  PCM at 24 kHz), which every player plays; with --raw, the SILK exactly
  as WeChat keeps it. A file already there is replaced.

ARGUMENTS AND OPTIONS
  <id>              the voice message's id, as `wxread messages` answers
                    it; required
  --chat <id>       the chat it is in, its id as `wxread chats` lists it (a
                    wxid, or a group's <n>@chatroom); required
  --out <path>      the file to write; required
  --raw             write the SILK as WeChat keeps it, byte for byte,
                    instead of a WAV
  --account <id>    the account to read, as `wxread doctor` names it;
                    with only one logged in, that one

WHAT IT ANSWERS
    account        the account read: its directory's name, as doctor's id
    chat           the chat read: its id
    id             the message's id, a string
    path           the file written, its absolute path
    format         "wav", or "silk" with --raw
    duration_ms    how long the sound lasts, in milliseconds, as decoded;
                   null for a --raw SILK that does not decode
    size           the bytes written
    length_ms      how long WeChat says the message is, in milliseconds;
                   null when it does not say
    transcription  the text WeChat heard in it, when the account converted
                   it to text in WeChat (转文字); null when it did not, or
                   WeChat heard nothing. `wxread messages` shows it too, as
                   the voice's transcription

TRIPS YOU UP
  - The id is the message's, as `wxread messages` answers it, and only
    finds it in the chat --chat names: an id of another chat, or of a
    message that is not voice, is an error saying so.
  - WeChat keeps the sound of a voice message only once it has it: one not
    downloaded yet, or one WeChat cleared, is an error whose fix is to play
    it once in WeChat on this Mac, then run this again.
  - wxread does not transcribe: transcription is WeChat's own, made only
    where the account chose 转文字 on the message in WeChat.
  - The keys must open every message database and every media database.
    One missing, or one that no longer opens its database, is an error
    naming the database; its fix is `sudo wxread keys`, then supplying the
    keys again.
  - Several accounts logged in is an error naming them: pass --account.
