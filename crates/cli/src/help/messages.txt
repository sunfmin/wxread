wxread messages: one chat's messages, each as its kind, newest first or,
with --oldest-first, from the first forward, a page at a time.

WHEN TO RUN IT
  To read a conversation, once `wxread chats` has named the chat. Run by
  you or an agent, once the keys are supplied; it changes nothing.

WHAT IT READS
  The account's message databases under its db_storage (message/
  message_<n>.db, and message/biz_message_<n>.db for official accounts)
  and contact/contact.db (and message/media_<n>.db, for whether WeChat
  holds a voice message's sound), each with the WAL beside it (what
  WeChat wrote last), with their keys: the file --keys names, else the
  contents of WXREAD_KEYS. Each is decrypted into memory and read there, after its key
  is checked against its first page; whether a media message's file and
  thumbnail are there is read from the files WeChat keeps under the
  account's directory. It writes nothing, anywhere: no decrypted byte
  reaches the disk.

OPTIONS
  --chat <id>       the chat to read, its id as `wxread chats` lists it (a
                    wxid, or a group's <n>@chatroom); required
  --from <time>     the first time read, itself included
  --to <time>       the time reading stops before, itself left out
                    A time is RFC 3339 with its offset
                    (2026-10-20T09:30:00+08:00, 2026-10-20T01:30:00Z), or a
                    date (2026-10-20), its midnight in UTC.
  --account <id>    the account to read, as `wxread doctor` names it;
                    with only one logged in, that one
  --limit <n>       how many messages a page holds, 1 to 1000; 100 unless
                    given
  --cursor <next>   start after the page that answered this `next`, with
                    the same --chat, --from, --to and --oldest-first
  --oldest-first    read the chat forward: oldest first, from its first
                    message (from --from, when given), each `next`
                    continuing forward; newest first unless given

WHAT IT ANSWERS
    account   the account read: its directory's name, as doctor's id
    chat      the chat read: its id
    messages  [{id, at, sender, sender_name, kind, <kind>, type, subtype,
              content}], newest first (oldest first with
              --oldest-first), those sent in one second in the order
              WeChat shows them:
              id           WeChat's server id of it, a string; null for one
                           the server never saw (some notices)
              at           when it was sent, RFC 3339 in UTC
              sender       who said it: a wxid; a recall's, who recalled
                           it; null for WeChat's other notices
              sender_name  what WeChat shows them as: the account's remark
                           for them, else their name in the group, else
                           their own name; null when nothing names them
              kind         what it is, one of the kinds below
              <kind>       an object named by its kind, of the fields
                           below: "kind": "quote" comes with "quote": {…}
              type         WeChat's number for it (1 text, 3 image, 49 an
                           app message, 10000 a notice, …)
              subtype      an app message's own type (5 a web page, 57 a
                           quote, …); 0 for none
              content      what WeChat keeps of it, as it keeps it: a
                           text's text, the XML of the rest; a group's
                           without the "<sender>:\n" WeChat starts it with,
                           decompressed when WeChat compressed it
    next      pass it as --cursor for the next page; null on the last one

THE KINDS AND THEIR FIELDS
  Every field is null when the message does not say it.
  Each media kind (image, video, file, sticker, voice) says whether
      WeChat on this Mac holds what `wxread file get <id>` writes:
      file_present its file, true or false (a sticker's, whether it
      names its address on WeChat's CDN, which is not fetched to tell),
      and thumbnail_present its thumbnail, an image's or a video's (null
      for the kinds that have none).
  text        {text}
  link        {to, title, summary, url, source}: to is "web_page",
              "music", "video", "mini_program", "channels_feed" or
              "channels_live"; source the site, account or mini-program.
              For a channels feed or live, title is its description (its
              author's nickname when it has none) and summary its
              author's nickname: WeChat's own title and description of it
              are a placeholder for clients too old to show it
  quote       {text, quoted: {id, sender, name, excerpt}}: the reply, and
              the quoted message's id, sender, name and, for a text, its
              words
  location    {latitude, longitude, name, address}
  card        {contact, name}: the contact the card shares
  forward     {title, messages: [{sender, name, at, kind, content, type,
              inside}]}: each message forwarded, in order; one forwarded
              inside another follows it, its inside the position in this
              list of the forward it sits in (null at the top)
  note        {items: [{kind, <kind>, sender, sender_name, at, type}]}: a
              note (笔记) sent into the chat, read as `wxread favorites`
              reads a favorite's note: each part of it, in order, as its
              kind with that kind's fields: its paragraphs (text {text}),
              places (location {latitude, longitude, name, address}),
              images (image {file_id, size, file_present,
              thumbnail_present}), files (file {file_id, size, name,
              extension, file_present, thumbnail_present}), links and the
              rest; type WeChat's number for the part (1 text, 2 image, 6
              place, 8 file). Its body as WeChat renders it is a file of
              extension htm, its first part. file_id is what `wxread file
              get <file_id> --out <path>` writes (note:<message>:<item>),
              size its bytes; a note's video or voice message has
              file_id and file_present null: where WeChat keeps it is not
              known. sender, sender_name and at are null: a note keeps
              none
  solitaire   {id, title, example, starter: {id, display_name},
              entries: [{number, member: {id, display_name}, text, at}],
              text}: a 接龙 (a sign-up list in a group), as this
              message shows it, each who adds or changes an entry
              sending it again; id WeChat's solitaire id, the same in
              every message of one 接龙, so the newest of them is its
              list now (null when WeChat's record holds none, as some
              do); title what it is for, without WeChat's "#接龙";
              example the line it gives entries to follow; starter who
              started it; entries in order: number its place (1 first),
              member who added it, text what it says, at when it was
              added (RFC 3339, UTC); each person by id and shown as the
              sender is; text all it shows, as WeChat shows it
  recall      {text, recalled}: a message its sender recalled, which
              WeChat rewrites into this notice in its place; its sender
              is who recalled it: the account for its own, else the
              member who goes by the name in quotes the text shows them
              by (null when none does, or several), in a direct chat the
              other; recalled the id of the message recalled, when
              WeChat's notice holds it (most do not: null)
  nudge       {from, to, text}: who nudged whom
  join        {contacts, by, text}: who joined the group, and who brought
              them in
  leave       {contacts, by, text}: who left or was removed, and by whom
  renamed     {name, by, text}: the group's new name, and who gave it
  transfer    {amount_fen, state, memo}: the amount in fen (1/100 yuan)
              when shown, state "sent", "received" or "returned"
  red_packet  {amount_fen, state, memo}: WeChat shows no amount
  call        {medium, state, seconds, text}: a voice or video call,
              medium "voice" or "video"; state "connected", "cancelled"
              (by the one who called), "declined" (by the one called) or
              "missed" (not answered), null when its text says none of
              these (answered on another device); seconds how long a
              connected one lasted (通话时长 01:04:50 is 3890), null for
              the rest; text what WeChat shows of it
  group_notice
              {text, by: {id, display_name}, at}: the group's notice
              (群公告) posted into its chat: its text; who posted it, by
              id and shown as the sender is; when it was posted (RFC 3339,
              UTC). `wxread group <id>` answers the notice it has now
  image       {name, md5, file_present, thumbnail_present}: name finds
              its file, msg/attach/<md5 of the chat id>/<YYYY-MM>/Img/
              <name>.dat under the account's directory, sealed
  video       {name, seconds, md5, file_present, thumbnail_present}: name
              finds msg/video/<YYYY-MM>/<name>.mp4 and <name>_thumb.jpg
  file        {name, stored_as, size, extension, file_present,
              thumbnail_present}: stored_as finds msg/file/<YYYY-MM>/
              <stored_as>; size in bytes
  sticker     {md5, url, file_present, thumbnail_present}: url its address
              on WeChat's CDN, md5 that of its bytes
  voice       {length_ms, transcription, file_present, thumbnail_present}:
              transcription the text WeChat heard in it, when the account
              converted it to text in WeChat (转文字); its sound is in
              message/media_<n>.db, by the message's id; `wxread voice <id>
              --chat <chat> --out <path>` writes it as a file that plays
  system      {text}: any other notice of WeChat's
  unknown     {}: anything else, read from content, type and subtype; a
              message whose XML does not read is unknown, never an error

TRIPS YOU UP
  - Messages are newest first: to read a conversation in the order it was
    said, pass --oldest-first and page forward with its `next`; there is
    no need to fetch every page and reverse it. A `next` keeps its order:
    one of an --oldest-first read given without it, or one of a
    newest-first read given with it, is an error naming the fix. Newest
    first, a message sent since the first page is not on a later one; a
    fresh run from the newest shows it. Oldest first, it is on the last.
  - The chat id is exact: a group's ends in @chatroom. A chat none of the
    account's message databases holds is an error pointing at
    `wxread chats`. A folder `wxread chats` lists (kind "folder") holds no
    messages of its own: it is an error naming the command that reads
    what it holds, its read_with.
  - The keys must open contact/contact.db and every message database,
    and when a page holds a voice message every message/media_<n>.db. One
    missing, or one that no longer opens its database (WeChat created its
    databases again: logging out and in, some updates), is an error naming
    the database; its fix is `sudo wxread keys`, then supplying the keys
    again.
  - Media is named, not fetched: `wxread file get <id> --out <path>`
    writes a media message's file, and `wxread file get <file_id>` the
    file of a note's image or file, by the file_id under note.items (the
    note's own id is not one). Its file_present says whether WeChat
    holds it, which it may never have downloaded, or cleared. `wxread voice`
    writes a voice message as a file that plays.
  - Several accounts logged in is an error naming them: pass --account.
