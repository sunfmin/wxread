wxread moments: the Moments (朋友圈) WeChat has loaded on this Mac,
newest first, a page at a time.

WHEN TO RUN IT
  To read what the account's contacts, and the account itself, posted to
  Moments: each post's text, location, link and media, and who liked and
  commented on it. Run by you or an agent, once the keys are supplied; it
  changes nothing.

ONLY WHAT WECHAT HAS LOADED
  WeChat for Mac keeps only the Moments it loaded while Moments were
  viewed on this Mac, and only the photos and videos it loaded then: not
  everything anyone ever posted, nor everything a contact's Moments hold.
  To have more listed, scroll further through Moments in WeChat (or a
  contact's own Moments page), then run this again. Likes and comments
  are as WeChat last loaded them: those since are not there until WeChat
  shows the post again.

WHAT IT READS
  The account's sns/sns.db under its db_storage, WeChat's store of the
  Moments it loaded, and its contact/contact.db, for names, each with the
  WAL beside it (what WeChat wrote last), with their keys: the file
  --keys names, else the contents of WXREAD_KEYS. Each is decrypted into
  memory and read there; no decrypted byte reaches the disk. For each
  medium it looks for the file WeChat cached under the account's
  directory (the one above db_storage), in cache/<YYYY-MM>/Sns, and reads
  none of it.

OPTIONS
  --account <id>   the account to read, as `wxread doctor` names it; with
                   only one logged in, that one
  --contact <id>   only the Moments this contact posted, by their id (a
                   wxid, as `wxread contacts` names it); the account's own
                   id for its own
  --limit <n>      how many Moments a page holds, 1 to 1000; 100 unless
                   given
  --cursor <next>  start after the page that answered this `next`

WHAT IT ANSWERS
    account   the account read: its directory's name, as doctor's id
    moments   [{id, author, at, text, location, link, media, likes,
              comments, type, content}], newest first:
              id         WeChat's id of the Moment, digits
              author     {id, display_name}: who posted it, by id, and
                         their name as WeChat shows it (the account's
                         remark for them, else their own name, else the
                         name the Moment gives; "" for none)
              at         when it was posted, RFC 3339 in UTC; null for
                         no time
              text       what its author wrote; "" for nothing
              location   {name, address, city, latitude, longitude}: where
                         its author tagged it, each "" (or null, for the
                         degrees) when not given; null for no place
              link       {title, description, url}: the article, song or
                         page it shares; null for none
              media      [{id, kind, url, thumbnail_url, width, height,
                         file_present, thumbnail_present}], in its order:
                id                 what `wxread file get` takes for it:
                                   <the Moment's id>:<its place, from 0>
                kind               image, video, or other (a link's
                                   cover, a song: no file of it is kept)
                url                where WeChat's CDN served it; "" for
                                   none. The CDN's addresses expire, and
                                   nothing is fetched from them.
                thumbnail_url      where it served its thumbnail; "" for
                                   none
                width              its width in pixels, when WeChat says;
                                   else null
                height             its height, the same
                file_present       whether WeChat holds its file on this
                                   Mac, which `wxread file get <id>`
                                   writes; null for other, and for one
                                   whose Moment gives no id of it
                thumbnail_present  whether WeChat holds its thumbnail (an
                                   image's smaller copy, a video's
                                   cover), which `wxread file get <id>
                                   --thumbnail` writes; null as
                                   file_present is
              likes      [{by, at}]: who liked it ({id, display_name},
                         named as author is) and when
              comments   [{by, at, text, reply_to}]: who said what and
                         when; reply_to the {id, display_name} of whom it
                         answers, null for none. A deleted comment is not
                         listed.
              type       WeChat's own type of the Moment, a number; null
                         when it gives none
              content    the Moment as WeChat keeps it: its XML
    next      pass it as --cursor for the next page; null on the last one

TRIPS YOU UP
  - What is listed is what WeChat loaded, not everything posted: an empty
    list, or a contact with fewer posts than they made, is WeChat not
    having shown them on this Mac yet.
  - A contact that posted nothing WeChat loaded, an id that is nobody's,
    and an account WeChat keeps no sns/sns.db for yet, are an empty list,
    exit 0, not an error.
  - A media's file_present false is an answer: `wxread file get <id>`
    answers it missing, exit 0, with what makes WeChat load it.
  - WeChat often caches only an image's thumbnail, the copy it showed in
    the feed: file_present false with thumbnail_present true is that, and
    opening the photo in WeChat's Moments caches it whole.
  - A Moment whose XML wxread cannot read is still listed, with its id,
    author and content: read its content.
  - Paging is by where each Moment was when the page was read: one WeChat
    loaded since is not on a later page, and a fresh run from the newest
    shows it.
  - The keys must open sns/sns.db and contact/contact.db. One missing, or
    one that no longer opens its database (WeChat created its databases
    again: logging out and in, some updates), is an error naming the
    database; its fix is `sudo wxread keys`, then supplying the keys
    again.
  - Several accounts logged in is an error naming them: pass --account.
